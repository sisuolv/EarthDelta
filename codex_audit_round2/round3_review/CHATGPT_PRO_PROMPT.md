## 材料/证据纪律

- Packet 里引用的原始 finding 原文（B01/B02/B10）是逐字复制自 round-2 的 `audit_findings.json`，可以直接当作事实使用，不需要怀疑其真实性；但**修复是否真的解决了 finding 描述的问题**，需要你自己重新从 diff 里核实，不要因为文档说"已修复"就采信。
- diff 是 `git diff` 的原始输出（unified diff 格式），`+` 开头是新增行，`-` 开头是删除行；请按 diff 实际内容判断，不要被 packet 正文的转述带偏——如果正文转述和 diff 实际内容对不上，以 diff 为准并明确指出不一致。
- 两个新测试文件是全文附上的，不是摘要；请检查测试断言本身是否真的验证了声称的行为（例如："fail-closed" 测试是否真的构造了"预期值缺失"的场景，还是只是换了个名字测别的东西）。

## 请你做的事（按顺序）

### 1. 逐条核对 B01 / B02 / B10 是否真的被关闭

对每一条，请给出独立判断（同意关闭 / 部分同意 / 不同意 / 证据不足），并说明理由：

- **B01**：exporter 是否真的不再复用受审的 `NormalizationContract`？零 diff_mean 是否真的在 exporter 独立路径里构造，而不是从 bridge 继承？`policy` 字段是否真的会改变 `digest`（即切换 policy 后，旧的 digest 缓存/身份标签不会被误判为"相同"）？
- **B02**：`verify_ckpt_sha256` 现在是否真的比较字节级 SHA-256（而不是只看长度）？`verify_normalization_parity` 是否真的比较 digest 内容？`x_raw` 参数是否真的被用来做 raw input hash 绑定，而不是摆设？`check_version_match` 是否真的接入了执行入口，还是仍然只是一个孤立可选 helper？6h_4step 文件现在是否真的会被加载并校验？
- **B10**：exporter 和 gate 是否真的共用同一套显式冻结的 checkpoint/config 参数？默认 checkpoint 是否已经改成 ps4（匹配 research spec 主线）？ps2 和 ps4 的产物目录是否真的隔离，不会互相覆盖？

### 2. 专项复查：fail-open 模式排查

Packet 里描述了父会话自己发现的一个问题：`verify_ckpt_sha256`、`verify_normalization_parity`、`verify_raw_input_binding` 在"调用方没提供预期值"时原本会静默 `passed=True`，等价于复现 B02 原始 bug；现已改为 `passed=False` + `IDENTITY_NOT_BOUND` 原因。

请你独立在 diff 里搜索是否还有**同类模式**没被这次修复覆盖到，包括但不限于：
- 其它 `if expected_X is None: passed = True`（或语义等价，比如 `passed = computed is not None`、`passed = True  # TODO` 之类）的分支；
- `verify_multistep_reference` 或其它未被 packet 正文点名的函数里，是否也有"缺参照就默认过"的逻辑；
- `find_upstream_reference_dir` 在多个身份标签目录匹配同一 patch_size 时"选最近的一个"，是否应该也算一种弱化的 fail-open（选错目录但不报错）；
- `GateIdentityConfig` 只在测试里被实例化、生产代码各自重算等价字符串这件事，是否可能导致两处 identity_tag 逻辑将来出现漂移而没有测试能抓到。

### 3. 检查测试是否"证明了它声称证明的东西"

对新增的 4 个 fail-closed 测试（`test_gate_fails_closed_ckpt_sha256_none` 等）和另外 10+15 个测试，抽查是否存在"测试名字听起来对，但断言太弱/断言了错误的字段/mock 掉了真正要测的逻辑"的情况。

### 4. 一致性检查

Packet 正文和附带的 diff/测试全文之间，是否有任何不一致（例如正文说"改了 3 个分支"，diff 里只看到 2 个；或正文说的行号和 diff 实际位置对不上）。

### 5. 明确说明局限

如果 packet 提供的信息不足以让你判断某个子问题（例如需要实际运行 GPU 上的官方 xformers 代码才能验证数值一致性，而这次全是 CPU 验证），请直接说"这一点无法仅凭静态 diff 判断，需要 Stage 2 真实 GPU S0 结果"，不要给出没有证据支撑的确定性结论。
