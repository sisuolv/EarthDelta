# 阶段 0 预算与最小计时

所有数字为计划上限，实际授权=MISSING。原审查估计2–3 H100卡时未经过计时，且新增ewma_g/delay30、扩展OCL信息和统计门后成本已变化。

建议总上限8 H100卡时：A3拟合/校准≤3、A4分析/诊断≤5，最多同时2张H100。资源按已分配卡数×墙钟计，空闲等待、启动失败、抢占重跑也计入。没有spot/多卡并行的免费计账例外。GPU由人按已批准范围执行，不在本轮提交。

## 1. 在首次拟合任务中测量

只用获准2020估计期、已QC输入。首个加载/缓存I/O与冷启动单列；2次预热后，在按日历排序的前8个有效估计日期上测 `t_roll20`、`t_roll4`、`t_grad4`、`t_grad2`，计时前记录具体日期。每项记录中位和p95、峰值显存、dtype/backend。每次测量前后同步CUDA；计时的试点结果可被相同身份的正式缓存复用，不能另重复预报只为计时。

20步官方/bridge无编辑一致性、零编辑和非零hook前向、4步反传方向/有限差分，是本次新运行所需数值门；旧S0只有1/4/12步不能直接覆盖。只做一次最小门，不为了材料重跑整套旧S0。失败立即记技术BLOCKED；有编辑梯度默认关闭checkpoint，不能用detach节省内存。

新方法代码不存在时，不拿别的模型计时冒充本模型。拟合候选数固定，按p95外推并预留20%；不能按分析技能缩小对照集合。

## 2. 保守卡时公式

以下按每GPU独立issue计算，所有 t 为秒。多卡分配的空等时间另计：

```
T = 361*t_roll20                         # 共享F0库的名义上界
  + 361*t_grad4                         # 含F0可微4步前向、反传及重算
  + 8*16*14*t_roll4                     # 4个单一族 + ewma_g的4个tau
  + 24*26*t_roll20                      # 选择期：8个候选方向各3个倍数
  + 5*270*t_roll20                      # 五个冻结参数臂
  + 39*(4*t_roll20 + t_grad2)            # truth_one_step、lag2、两次buf12
  + T_precheck_and_extra_timing          # 数值门、预热及不能复用的额外计时
  + T_io_startup_failed_allocated
H100_card_hours_upper = 1.2*T/3600
```

两个授权池还要分别核算，不能用总额未超预算掩盖单池超额：A3的名义上界是 `86*t_roll20+86*t_grad4+8*16*14*t_roll4+24*26*t_roll20+数值门/额外计时+拟合启动I/O/失败`；A4是 `275*t_roll20+275*t_grad4+5*270*t_roll20+39*(4*t_roll20+t_grad2)+分析启动I/O/失败`。分别乘1.2/3600，检查≤3与≤5；两者相加必须与总公式一致。数值门及预热不得遗漏或与可复用库重复记账。

F0和梯度存储按缺失后可用数执行，但预算使用名义上界。梯度不能由缓存的无梯度F0预报场直接反传，需要重新执行可微短前向，已包含在`t_grad4`。lag2使用已缓存梯度，不能重复计成额外4步梯度作业。诊断中truth_one_step沿用worker的当期梯度，只可给诊断scorer，不能进入actor。

预热需要F0库和梯度/残差记录，但无需五个参数臂的20步预报。发生新需求必须先改预算，而不是漏计。

## 3. 存储与CPU

以D=6×1024²为当前参考（实际从模型推断），raw FP32梯度名义361条约9.1GB；另存FP64范数。不要为了节省约4.5GB而默认直接存原始fp16梯度。

F0库保存六变量×步骤1,2,3,4,12,20，约4.7MB/issue、1.7GB总量；校准/诊断需要第4步全69通道的状态标准化预测，按注册子集另存，约0.5GB量级。没有可微图持久化。缓存身份和缺失占位比节省少量磁盘更重要。

CPU统计校准按STATISTICAL_PLAN时间盒执行；超时为未完成统计资格，不自动增加模拟轮次。T2预计2人日，拟合与报告各约1人日。A3/A4前分别按已经发生的实际卡时检查剩余上限，超额停下，不能自动申请后续年份。
