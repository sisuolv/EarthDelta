本文回应“参考 Pro 整合的 plan，详细思考后续怎么做”。它是实施建议，不是实验结果，也不把附件中的授权模板视为本次已经下达的训练指令。原始 ZIP 与解压内容保留不变。

## 1. 判断：值得开展一轮有上限的真实实验，当前优先获取决策证据

我赞成 Pro 的主要调整：把后续投入集中到“小而合格的专家库、完整候选结果、合法策略、强对照”上。现阶段最缺的是：是否存在超出强静态方案的动态空间，以及这种空间能否由起报时可用的信息利用。更多模块或更多审计条目，不能替代这两个答案。

建议保留四个独立问题，分别做出结论：

| 问题 | 最小证据 | 通过以后仍不能声称什么 |
| --- | --- | --- |
| 所选系统是否测得准？ | 独立官方推理对齐、身份绑定、统一原生评分、实际数据切片准入 | 不证明编辑有价值 |
| 这个库是否有动态空间？ | 同起报完整候选 oracle，相对强静态和固定候选的余量 | 不证明在线可预测 |
| 合法选择是否有效，双头是否提供增量？ | 独立评估的 regime/direct-gain/dual，原生实际结果结算 | 双头有效不自动证明必须真正执行参数编辑 |
| 实际编辑是否值得支付成本？ | 同信息和资源口径的 virtual、联合输出纠错、反馈纠错 | 一个有限配置的胜出不等于通用优越性或全领域新颖性 |

研究价值判断仍是“有界继续”，全局 novelty 仍未得到证明。无需先完成新一轮大范围文献审计才做小实验；若实验支持具体贡献，再围绕最终主张补齐近邻文献。当前应优先检验固定库下的合法动态收益，再条件性检验分解的标签/成本优势。singleton-only 的最小库不能同时承担“未见动作泛化、非线性组合交互、完整二次规划”这些主张。

## 4. 我建议的实际顺序

### 第一步：完成一个可信的测量闭环

范围是 `R2-P0-01`。先修使用路径、跑针对性合成测试，再在具备实际资源的执行阶段做所选 checkpoint 的独立官方对齐。

最低验收内容：

- 一个 canonical 配置绑定 checkpoint、patch size、官方 commit、normalization policy、变量/单位/坐标、输入、dtype、interval、步数和容差。优先沿用 ps4 历史规格；任何改用 ps2 都应明确改变实验对象。
- 官方参照独立构造 transforms，不复用待验证的 NormalizationContract；至少验证一步和本轮所用多步路径。容差以数值误差依据登记，不能为了通过而放宽。
- 原生 `[B,H,V,Lat,Lon]` 上只归一化一次的目标；候选保留 K 轴。非均匀变量/时效/面积权重的合成例子必须满足 `gain = loss_ref - loss_edit`。
- 非零合成 bank 的 `zero -> nonzero -> zero`、异常退出后的 hook 清理、冻结 backbone 与 bank 梯度；零初始化 LoRA 不能证明编辑有作用。
- 实际消费的数据通过 exact time lookup 与内容检查。shape、日历 manifest、marker 只能用于定位，不能代替完整性证据。

这一步的交付应是小而可审查的补丁、针对性回归结果、配置身份和真实 S0 的独立状态。若真实 S0 尚未运行，只写 `CPU_VALIDATED / NOT_RUN 或 BLOCKED`，研究判断保持 `NOT_EVALUATED`。它的完成标准不是“测试数量增长”。

### 第二步：先测成本，再冻结强静态参考与一个小库

对应 `R2-P0-02` 的前半段。先测单步、多步推理、一个 bank 更新和缓存写入的真实成本，再确定 K/rank/样本上限。LoRA 可训练参数少，并不保证多步反向传播、缓存或吞吐便宜。

建议把下列作为起始候选配置，按资源 profile 冻结，而不是未经测量的硬性参数：

| 项目 | 起始建议 | 目的 |
| --- | --- | --- |
| Backbone | 一个 checkpoint，一种官方归一化，一种 6h 推进路径 | 避免多个系统混在同一指标里 |
| Reference | 先训练或核验 Fs，再冻结 Fs 训练动态 bank | 动态选择必须面对足够强的静态参考 |
| 专家与候选 | 2–4 个专家，显式 no-edit，先各一个训练覆盖的非零强度 | 限制全候选仿真和调参成本 |
| 作用窗 | 一个固定 hold 窗口 | 先回答有无信号，避免窗口搜索消耗开发集 |
| 目标 | 可考虑 24h 主目标、6h 诊断、72h guard；具体变量/Q 在运行前冻结 | 保留早期收益与后续损害的区别 |
| 训练时域 | profile 后决定 6h/24h 训练，72h 可先只做推理 guard | 避免首轮因长链反传而被迫增加重放框架 |
| 复杂选项 | 首轮不开负幅度外推、连续系数搜索或大量 pair | singleton 结果只解释 singleton 假设 |

F0、Fs 和 best-static 必须分清：F0 是原始骨干；Fs 是训练后的固定参考；best-static 是在开发训练侧选定、对所有评估起报都使用同一 ID 的候选。动态动作首先要超过 Fs 和这个固定候选。另报告参数规模匹配与总训练成本匹配的静态对照，不声称两者天然相等。

官方 S0 首先对齐 F0 路径；加入 Fs 后，还要验证静态 adapter 的重构、合并或常开执行的等价性，并把冻结 Fs 身份纳入新的参考记录。F0 的数值参照不能原封不动作为 Fs 的参照；固定库训练也无需在每次优化更新后重跑整套官方审计。

Fs 最容易出现的执行错误是：训练时存在静态 adapter，no-edit 或 hold 结束以后却落回 F0。可采用“独立加载后合并静态 adapter”或“经过等价性测试的 always-on 分支”之一；保持官方 checkpoint 文件不变。编辑窗结束应从被编辑后的状态继续 Fs 动力学。

专家库资格也不能只检查非零。若所有专家以同样数据、目标和初始化方式学到几乎相同的静态修正，动态余量小是可预期的。需要预先给出有依据的训练差异，例如 fit-only 的合法 regime 分组或少量明确的训练目标差异，并记录响应多样性与训练机会。多样性只用于资格和诊断；不按 dev/confirm 收益删掉坏专家，也不将任意正则正交性等同于天气价值。

### 第三步：同一份完整缓存，先回答 oracle 与 cheap legal 两个问题

对应 `R2-P0-02` 后半段与 `R2-P0-03a`。03a 是对原任务内部执行顺序的建议，不是新增一套任务编号系统。

对每个注册起报，从相同初态运行 Fs 和全部注册候选，保存实际非线性结果。联合候选若注册，必须实际运行；不以单专家响应加法冒充。缓存保留全部候选、失败记录、机会分母及可追溯的向量结果/重算路径。

同一缓存首先产出五行比较：no-edit/Fs、冻结 best-static、fit-only regime、低容量 ridge/direct-gain、完整 oracle。regime/direct 的模型训练和选择只能用外折训练侧，外折起报不得进入 bank 训练。这里最有价值的两个差值是：

```text
dynamic_headroom = V_oracle - V_fixed
usable_gain     = V_cheap_policy - V_fixed
```

同时单列相对 Fs 的收益及 guard。oracle 很好而 cheap 没信号，不是成功；cheap 没信号也不证明所有合法策略都不可能成功。此时只有在 oracle 与瓶颈诊断支持下，才值得给一次事先封顶的更强挑战。不能自动开启新 encoder、memory、JEPA 或无限调参。

预算必须为这一步保留策略检验份额。只得到昂贵的 oracle 表、没有资源验证合法预测，会使本轮最重要的问题继续悬而未决。

### 第四步：有合法信号后，再集中比较 dual 与 direct

对应 `R2-P0-03b`。复用同一 bank、候选表、legal features 和时间划分，比较同资源的 direct-gain 与 e0/du 双头；先跑一个可诊断的预算点，再按预登记的少量标签点扩展。若 cheap 无信号，这一步只能是上一步所述的一次有理由的有界挑战。

直接收益监督由一条起报真值生成所有候选标签，不能给 direct 按 K 倍计算标签成本。双头若获得额外无真值响应仿真预训练，direct 也应获得可用的同等辅助训练方案，而不只是纸面上的“允许使用”。主比较以实际选中候选的原生收益为准。

四格诊断要在同一库中真实替换 e/u，并用真实结果表结算：true/true、true/pred、pred/true、pred/pred。前三格只用于定位瓶颈，不能作为在线能力；全场误差 R² 低也不单独构成停止理由。

### 第五步：只有前面值得继续，才支付输出纠错挑战成本

对应 `R2-P0-04`。比较实际编辑、预测响应直接加到参考上的 virtual、联合多时效输出纠错，以及在 hold 内逐步反馈的输出纠错。feedback 使用自身预测状态推进；不喂未来真值。

若 dual 没有额外价值，但 direct 动态选择有效，仍可围绕“合法动态选择是否需要真实参数编辑”做范围更窄的 E3；应明确这是修改后的研究主张。不能为了保住原始双头叙事而忽略有效的 direct 结果。

若只有压缩响应、没有经过验证的原生 lift，virtual full-field 对照尚未完成。不能从 summary 上的非劣结论推断全场等效。对于实际编辑，preview、重放、adapter、回退都计入在线成本。

## 5. 双头阶段必须预先想清楚的两个技术问题

### 5.1 输出压缩是否已经损失了决策空间

variant_2 已正确要求最终用 native 目标结算，同时允许训练输出使用固定线性 D。这两个要求应保留，但还需一个便宜的诊断顺序：

1. 用原生真实 e、u 计算完整候选 oracle。
2. 用 fit-only 冻结 D 下的真实 e_D、u_D 选动作，再在原生结果表结算。
3. 比较两者的原生 regret、选项差异和相对静态的余量。
4. 再把 e_D/u_D 换成预测值，研究学习损失了多少额外收益。

如果第 2 步已经丢失大部分可用余量，那么该压缩表示不适合当前决策。直接训练更大的 head 很可能无济于事，也不能把结果解释成整个双头思想失败。D 必须只用拟合侧确定；外折和确认结果不能反过来选 D。

这也影响 direct/dual 比较的解释：direct 用 native gain 标签，dual 用压缩向量标签时，比较包含了表示近似的影响。可把决策相关的固定响应基作为一个有限诊断；无需一开始另立大型表示学习项目。

### 5.2 两个条件均值代入恒等式，未必等于条件期望收益

以下是前次审计已经提出、variant_1 的条件矩方案部分回应的问题，并非本次新发现。

固定动作 a 和 Q，令 `mu_e = E[e|I]`、`mu_u = E[u_a|I]`。若两个头分别以 MSE 学习条件均值，则真实期望收益为：

```text
E[g_a | I]
  = 2 mu_e^T Q mu_u - mu_u^T Q mu_u
    + 2 tr(Q Cov(u_a,e | I)) - tr(Q Var(u_a | I)).
```

压缩 context I 可能使响应 u 在给定 I 后仍有变化，均值双头就遗漏了协方差和响应方差。若 I 包含决定响应的全部输入且模型确定，则这些条件项消失；此时问题主要回到有限容量、样本和预测误差。不能把这一条件风险写成“双头一定不成立”。

建议预先登记失败诊断，而不是强制首轮同时实现所有变体：先检查表示损失、四格与排序误差；若证据指向上述瓶颈，可以在同缓存、同预算内比较一个条件矩版本，例如分别预测 `E[e^T Q u_a|I]` 和 `E[u_a^T Q u_a|I]`。有限候选下它与 direct-gain 已很接近，主要用于理解失效原因，不能自动包装成新的分解创新。

## 6. 资源、标签与统计怎样真正落地

### 缓存先做字节预算

以完整 69 通道、128×256 原生网格和 FP32 为例，一个状态占 `69*128*256*4 = 9,043,968` 字节，即约 9.04 MB。仅保存三个时效时：

| 示例配置 | 1,000 个起报的候选预测 | 额外真值 |
| --- | --- | --- |
| 共 5 个候选，含 no-edit | 135.66 GB | 27.13 GB |
| 共 9 个候选，含 no-edit | 244.19 GB | 27.13 GB |

这里是未压缩十进制字节算术，不是机器实测，也不表示建议使用 1,000 个独立过程；1,000 个起报可能高度相关。还未计输入、训练中间量、重复保存的 response 或其它日志。若只注册部分变量、使用经核验压缩或不同 dtype，预算应按实际对象重算。

优先按起报/候选顺序分片，只存必要时效；在验证后选择压缩，记录数值误差。若只留下 scalar gain 或 winner，后续 du 学习和四格诊断需要重新模拟，应提前计费。可以保留原生得分与完整可重算指针，加必要的向量目标，但“能重算”必须在资源上可兑现。

在线效率也需总账：

```text
C_total(N_deploy)
  = C_static_and_bank + C_cache + C_heads
    + N_deploy * C_online
```

direct-gain 同样能避免在线逐一运行 K 个候选，所以双头的效率对手应包含 direct；只相对离线 oracle 宣称省计算没有说服力。使用实测成本和不同部署次数的敏感性分析，不预设一定可以摊薄。

### “少标签”要对应真实瓶颈

ERA5 回顾实验已有大量真值，昂贵的部分可能主要是候选仿真而非获取标签。应在投入标签曲线前说明：研究的是新区域/新时段监督稀缺、真值延迟，还是一个明确的统计样本效率问题。

保留 Pro 的两个账本，并在结果标题里使用：

- `given-bank/controller`：bank 已固定，策略额外需要多少核验起报。
- `end-to-end`：计入 Fs/bank、特征或输出基、全部 HPO 和策略学习用过的核验起报。

bank 已消耗大量标签时，减少 head 标签只能支持第一种主张。若实际优势最终是低推理成本或动态效果，就围绕那个结果写论文，不必强行保留少标签叙事。未见动作泛化需要额外冻结动作训练/测试协议，不能由固定候选内标签曲线代替。

### 把已经正确的统计要求填成具体配置

Pro 已写明 bank-disjoint 外层评估、fit-only 变换、起报/过程分组、history/target 边界处理、一次性 confirm、MDE 与价值阈值区别。这些并非缺失；剩下的是冻结具体时间块、排除边界、起报等权还是过程等权、主比较、guard、失败回退和最大样本数。

默认用 bank 未见的策略开发块做 crossfit，避免每个外折重训大 bank。每折的标准化、聚类、输出基与 HPO 仍只能接触训练侧。OOF 开发结果如果反复用于选方法，仍是开发证据。

最终确认在 E1/E2/E3 所有拟比较的方法、阈值和分析程序冻结后一次执行。用于 S0/debug/profile/调参的时段明确标 exposed；不能因为脚本名称不同就反复使用同一 confirm。

价值阈值回答“多大收益值得投入”，功效/MDE 回答“这个预算能否分辨该收益”。如果预算不足，允许以 `INCONCLUSIVE` 停止开销；不能降低阈值直到得到 PASS。正式继续要求相应置信区间下界超过价值阈值；上界低于阈值可排除最低价值；覆盖边界则不足以判定。训练策略的不确定性和固定策略在新过程上的不确定性应分开说明，避免把单次拟合后的 CI 解释成整个训练算法的稳定性。

## 7. 结果出来以后怎么决策

| 观察结果 | 合理结论 | 后续动作 |
| --- | --- | --- |
| 对齐/身份/评分/数据准入失败 | 当前测量不可信 | 修同一路径；不作科学否证 |
| 库未训练、响应近零或候选不完整 | 库/取证不合格 | 先解决资格；不宣称方向失败 |
| 合格完整库的 oracle 也不足 | 当前库、目标、预算下空间有限 | 停当前库；扩库需要独立依据和新协议 |
| 静态有用，动态余量被有力排除 | 静态适配更合算 | 转静态，停止大 planner 投入 |
| Oracle 好，cheap 无信号 | 尚未找到可利用信号 | 有诊断依据时给一次封顶挑战；否则停止当前配置 |
| Direct 有用，dual 的最小增量被排除 | 动态选择成立，双头主张不成立于当前范围 | 转 direct；E3 可在缩窄主张后继续 |
| Dual/direct 差异 CI 很宽 | 分解比较尚不确定 | 按已定预算结束或预注册追加；不称等效或否证 |
| 合法策略有效，virtual/output/feedback 更合算 | 实际参数编辑的必要性受挑战 | 转响应代理或输出纠错 |
| 合法动态收益、分解增量和有限成本优势都有证据 | 原主张得到有限范围支持 | 围绕该范围规划后续扩展与论文 |
| 达到资源上限且统计仍不足 | 本轮证据不足 | 保留结果，停止支出；不以新增模块代替答案 |

开发期只标 `DEV_PROMISING` 等探索状态。上表涉及“排除最低价值”“成立”等正式表述时，均要求完整资格、已注册阈值和相应置信区间证据。负结论或提前停止，也应生成最终记录；不必为了完成 DAG 而继续被证据切断的分支。
